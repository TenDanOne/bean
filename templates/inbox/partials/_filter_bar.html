{% comment %} A named window rather than two date pickers. "Last 7 days" is the question people actually ask, and making them enter two dates to express it is three interactions for one thought. Both of these keep the publication folders — narrowing by date leaves the publications intact, and a folder counting only what passed the filter is exactly what makes "which video still has old comments" answerable. {% endcomment %} {% comment %} A switch, not a menu. An icon-only button that toggles between two states — the arrow for descending (newest first) or ascending (oldest first) — with no select arrow, because there is no list to open. The filter bar lives outside the #inbox-message-list swap target, so its markup never re-renders and the request must carry the new value itself. HTMX 2 binds a click listener on the element before Alpine (defer) does, so a declarative hx-vals is read *before* @click toggles the state — the request always shipped the previous sort and the list never reordered. Making Alpine own the whole interaction fixes it: @click flips `sort`, then fires htmx.ajax with the freshly toggled value via `values`, and the other filters are still collected through `hx-include` on the source element. Working a backlog from the bottom means answering whoever has been waiting longest, which is what the SLA this inbox tracks is about. {% endcomment %}
